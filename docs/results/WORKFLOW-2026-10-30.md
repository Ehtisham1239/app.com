# Monthly teacher report, review and certificate workflow

Owner scope: teacher fills the result form; admin edits before approving and publishing; OQC logo and green/gold result certificate. Existing completed modules are reused. No new unrelated modules, accounts, prices, SEO, analytics, grading scheme or production student data changed.

## Existing implementation retained

- `/admin/progress/assignments`: link existing teachers to their students.
- `/admin/progress/form`: reporting month, six existing rating categories, remarks, draft and submission.
- `/admin/progress`: admin review queue. Open a report, choose **Edit**, supply a correction reason, save, inspect the certificate, then **Approve & publish**.
- `/parents`: linked guardians see only the published snapshot; a draft correction does not replace it until republished. Submitted reports are locked to teachers pending review. History records corrections/publication.
- Existing database routines and RLS are installed on app.com project `lgbwidraztavhhbnbfhr`. Read-only inspection confirmed the three progress tables have RLS and the save/edit/publish/parent routines exist. No migration or production report mutation was needed in this change.

## Completed in this revision

- Matching three-stage workflow indicator on teacher and admin review screens.
- Teacher editor state belongs to a loaded student/month/report revision rather than being reset by a later effect. Switching learners cannot display another student's saved values.
- A failed report fetch shows an error/retry instead of a blank form that could overwrite an existing report. A referenced but unavailable report is not editable.
- Failed saves retain entered text, release the busy state and allow retry. Student/month switching is disabled while saving.
- Clear published-snapshot guidance while making revisions.
- Existing OQC branded certificate retained with safer long-name/remark wrapping and print break avoidance.
